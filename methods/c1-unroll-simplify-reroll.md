# C1 展开、化简、再分块（unroll, simplify, re-roll）

## 1. 一句话判断

这是把命题个数压下两个数量级的主要手段之一：原始版本的引理边界是生成时留下的，不是数学上的边界；把它们展开、跨边界化简、再按真正的复用重新切开，才谈得上结构性缩小。代价是必须理解证明。

## 2. 做什么

1. 固定最终陈述与证明骨架。
2. 把只用一次的引理、包装定义、命名的 `Prop` 内联，得到一条长而平的证明。
3. 在展开后的证明里找跨原边界的化简：重复的子推导、绕远的中间结论、可以直接用库引理的步骤。
4. 按真正被多处复用的结论重新切成引理，陈述写到自然的通用程度（[C2](c2-statement-generalization.md)）。

## 3. 谁在用

- grh-lean（Luke Sernau 与 Anthropic 同事，借助 Claude） [D16]：作者在 Zulip 上只给了这一句方法描述，原意是把定义展开成长而平的证明，在那里找化简，再卷回去，这样可以跨边界化简 [z643710501]。
- 理论先例：切规则引入（反转切消，自动引入引理） [P17]、发明新定义 [P16]、HOL Light 的引理挖掘 [P18]。
- 同方向的基准：Leanify（压缩越往后，发现的非平凡引理越多） [P29]、LeanLean（仓库级压缩的大头来自依赖重组） [P30]。

## 4. 证据等级

- **作者自述**：只有上面那一句，作者表示方法不能多说 [z643710501]。
- **推测**（我们从成品代码推断，见 [grh-compact-vs-original](../docs/grh-compact-vs-original.md)）：重新分块确实发生了，证据是下表的结构差异；具体流程、用了什么工具、多少由人多少由模型，都不知道。

## 5. 作用层级

小仓库到大仓库。需要理解数学。

## 6. 正确性靠什么保证

- 只能靠最终闸门：陈述文件原样保留，用 comparator 与多个独立内核检查（[E2](e2-verification-gate.md)）。grh-lean 两个版本都在发布当天由 MIT 用六个检查器核验 [D18]。
- 中间状态没有保证，所以必须在独立分支上整体完成，不能逐 PR 合并。

## 8. 代价与坑

- 需要读懂整段证明；对 1,700 万行的原始版本，作者是在保留骨架的前提下重写，而不是逐行展开。
- 展开后的中间证明可能极大，编译与内存成本高；只适合局部分段做。
- 结果与原始代码几乎没有可对齐的名字（紧凑版的名字只有 14% 在原始版本出现过），无法逐 PR 审阅。

## 9. 什么时候用

机械路线（A 层）到顶之后；与 [C2](c2-statement-generalization.md)、[C3](c3-unwrap-statement-layers.md) 同时做，之后接 [D3](d3-thin-then-thick.md) 为阅读展开。

## 10. 未解决的问题

- 如何在中间阶段给出部分保证，使它可以分批审阅？
