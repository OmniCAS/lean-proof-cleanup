# C2 把陈述写到通用对象上（statement generalization）

## 1. 一句话判断

命题个数下降的主要来源之一：原始版本的引理大多绑在项目自己的数据包和一串尺度假设上，只能用一次；改成对任意数域、任意矩阵陈述，一条引理就能替代一族特例，还能直接接上 Mathlib。

## 2. 做什么

- 找出只在项目数据结构上陈述的引理，把参数换成通用对象（数域、环、矩阵、线性映射），去掉证明用不到的假设。
- 把一族只差参数的特例合并成一条带参数的引理；公共参数放进 `variable`。
- 对可以进 Mathlib 的通用结论，按 Mathlib 的写法陈述，便于后续上游（[C4](c4-upstreaming-known-math.md)）。

## 3. 谁在用

- grh-lean 的两个短版本：样例见 [grh-compact-vs-original](../docs/grh-compact-vs-original.md) §2（`classNumber_le` 从项目数据包 `D7` 加五条尺度假设，改成对任意数域的教科书式上界；`trace_pow_eq_sum_roots` 从选定基下的线性映射改成直接对矩阵）。
- 背景库 `Lib/`（紧凑版 573 个文件）按数学主题组织，是 Mathlib 缺少的通用材料 [D16]。
- 相关工作：Hierarchy Builder 与 Mathlib 的实例参数研究 [P22] [P23]；MathlibLemma 的常识引理挖掘 [P36]。

## 4. 证据等级

- 短版本里普遍存在：本仓库测（样例与统计）。
- 它是作者有意采用的方法：推测（作者没有这样说；README 只说背景材料"从原证明移植再重写"）。

## 5. 作用层级

文件到大仓库。需要理解数学（判断哪个通用程度是自然的）。

## 6. 正确性靠什么保证

- 新陈述更强，旧的特例可以由它推出；只要最终陈述不变、闸门通过即可。
- 风险在于通用化时悄悄加了假设或改了定义；陈述层面的人审不可省。

## 7. 效果

| 数字 | 标记 |
|---|---|
| 同一个短名被定义多次的名字：原始 98,631 个，可读版 378 个，紧凑版 225 个 | 本仓库测 |
| 原始版本重复最多的短名：`Statement` 4,225 次、`proof` 3,234 次、`main` 2,922 次 | 本仓库测（[grh-compact-vs-original](../docs/grh-compact-vs-original.md)） |
| 紧凑版 9,916 个声明名里只有 1,344 个（14%）在原始版本出现过 | 本仓库测 |

## 8. 代价与坑

- 通用陈述的证明有时更长，要权衡复用次数。
- 改动跨越大量调用点，必须整体完成，不适合逐 PR 合并。
- 对 Mathlib 版本更敏感（通用陈述直接用 Mathlib 的接口）。

## 9. 什么时候用

与 [C1](c1-unroll-simplify-reroll.md) 一起做；在 [C4](c4-upstreaming-known-math.md) 之前（先通用化，再上游）。
